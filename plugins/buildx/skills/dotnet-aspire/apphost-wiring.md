# AppHost Wiring

Inside `AppHost/Program.cs`. Decide for each consumer: which **registration verb**, which **startup operator**, which **endpoints**, and which **dependencies**. The decisions follow from what the project actually does — not from naming conventions.

## 1. Discovery: read the project before wiring

Before adding `AddProject<T>(...)`, open the consumer's `Program.cs` and `.csproj`. Three signals fully classify it:

| Signal | Meaning |
|---|---|
| `<Project Sdk="Microsoft.NET.Sdk.Web">` + `WebApplication.CreateBuilder` + `app.Map*` calls | Web (HTTP) — auto-start, expose endpoints. |
| `MapGrpcService<T>()` or `Grpc.AspNetCore` package | gRPC — auto-start, **HTTPS** endpoint required. |
| `<Project Sdk="Microsoft.NET.Sdk.Worker">` or `Host.CreateApplicationBuilder` + `AddHostedService<T>` | Worker — auto-start, no HTTP. |
| `<Project Sdk="Microsoft.NET.Sdk">` + top-level statements that finish (no `WebApplication`, no hosted service, no infinite loop) | CLI / one-shot — `WithExplicitStart()`. |
| `package.json` with `vite` / `next` / `react-scripts` | JS frontend — `AddViteApp` / `AddNpmApp`. |
| Dockerfile in repo and no .NET project | Container built from source — `AddDockerfile`. |
| Pre-built image consumed as-is | `AddContainer`. |
| Arbitrary native binary | `AddExecutable`. |

Mixed cases (e.g. a Web API project that ALSO exposes a gRPC service) get the more restrictive treatment — both endpoints, both clients.

## 2. Registration verbs

| Verb | Argument | Returns |
|---|---|---|
| `AddProject<T>(name)` | `T` is `Projects.{Sanitized_Name}` (generated by Aspire SDK) | `IResourceBuilder<ProjectResource>` |
| `AddProject(name, csprojPath)` | string path | same |
| `AddExecutable(name, command, workingDir, args...)` | path + args | `IResourceBuilder<ExecutableResource>` |
| `AddContainer(name, image, tag?)` | image + optional tag | `IResourceBuilder<ContainerResource>` |
| `AddDockerfile(name, contextPath, dockerfilePath)` | repo-local Dockerfile | `IResourceBuilder<ContainerResource>` |
| `AddNpmApp(name, workingDir, scriptName?)` | path to `package.json` dir | `IResourceBuilder<NodeAppResource>` |
| `AddViteApp(name, workingDir, packageManager?)` | path to `package.json` dir | `IResourceBuilder<NodeAppResource>` |
| `AddYarnApp` / `AddPnpmApp` | … | … |
| `AddExternalService(name, url)` / `AddExternalService(name, urlParameter)` | URL or `IResourceBuilder<ParameterResource>` | `IResourceBuilder<ExternalServiceResource>` |
| `AddConnectionString(name)` / `AddConnectionString(name, ReferenceExpression)` | external-only or composed | `IResourceBuilder<ConnectionStringResource>` |
| `AddParameter(name, default?, secret: bool)` | configuration-driven value | `IResourceBuilder<ParameterResource>` |

Vendor-specific verbs (`AddPostgres`, `AddRedis`, `AddAzureCosmosDB`, `AddAzureServiceBus`, `AddAzureStorage`, `AddSqlServer`, …) extend `IDistributedApplicationBuilder` from their hosting NuGets and follow the same shape. See [emulators-and-real-infra.md](emulators-and-real-infra.md).

## 3. Startup operators

| Operator | Effect |
|---|---|
| (default) | Resource starts when AppHost starts, in dependency order. |
| `.WithExplicitStart()` | Resource declared but not auto-started. User clicks "Start" in the dashboard, or another resource calls `WaitFor`/`WaitForCompletion` on it, or test code drives it explicitly via `app.ResourceNotifications`. |
| `.WaitFor(other)` | Block this resource's startup until `other` reaches **Healthy**. Most common dependency operator. |
| `.WaitForStart(other)` | Block until `other` reaches **Running** (skip the health-check gate). Use when `other` has no health check or is intentionally slow to become healthy. |
| `.WaitForCompletion(other)` | Block until `other` finishes and exits cleanly. Used for setup tasks (migrations, seed scripts, init containers). |
| `.WithLifetime(ContainerLifetime.Persistent)` | Container survives across `aspire run` invocations (preserves data volumes between sessions). |
| `.WithLifetime(ContainerLifetime.Session)` | Default. Container dies with the AppHost. |

### `WithExplicitStart` is mandatory for one-shot CLIs

A CLI registered with `AddProject<T>("migrate")` and **no** `WithExplicitStart`:
1. Aspire starts it on `aspire run`.
2. The CLI does its work and exits with code 0.
3. Aspire considers the resource "stopped unexpectedly" and **restarts it**.
4. Loop.

The fix is one of:

```csharp
// Option A: developer-triggered (manual click in the dashboard)
var migrate = builder.AddProject<Projects.Contoso_Foo_Migrations>("migrate")
    .WithExplicitStart();

// Option B: dependency-triggered (run before "api" starts; api waits for migrate to finish)
var migrate = builder.AddProject<Projects.Contoso_Foo_Migrations>("migrate")
    .WithReference(db).WaitFor(db)
    .WithExplicitStart();

builder.AddProject<Projects.Contoso_Foo_Api>("api")
    .WithReference(db)
    .WaitForCompletion(migrate);   // implicitly starts `migrate`, blocks `api` until exit
```

`WaitForCompletion` on an explicit-start resource implicitly fires the start.

## 4. References (data-plane wiring)

`WithReference(other)` injects the right environment variables for the consumer to discover `other`. The injection shape depends on `other`'s type:

| `other` is | Env vars injected |
|---|---|
| `IResourceBuilder<IResourceWithConnectionString>` (DBs, Service Bus, custom connection strings) | `ConnectionStrings__<name>` |
| `IResourceBuilder<IResourceWithEndpoints>` (projects, containers, external services) | `services__<name>__<endpoint>__0`, plus `services__<name>__<endpoint>__1` for fallbacks |
| `IResourceBuilder<ParameterResource>` | `Parameters__<name>` (or whatever name the consumer reads) |

Consumers use these via:
- `builder.AddNpgsqlDataSource("db")`, `builder.AddAzureCosmosClient("cosmos")`, etc. — read connection strings.
- `builder.Services.AddHttpClient<T>(c => c.BaseAddress = new Uri("https://api"))` + `AddServiceDiscovery()` — service discovery resolves `https://api` to `services__api__https__0`.
- `builder.Configuration["Parameters:foo"]` — read parameters.

### `WithReference` on `AddExternalService`

Service discovery for HTTP services Aspire does not start. Useful when the same logical name (`partner-api`) needs to swap between a stub container in dev/test and a real URL in real-mode:

```csharp
var partnerUrlParam = builder.AddParameter("partnerApiUrl");

var partner = builder.AddExternalService("partner-api", partnerUrlParam)
    .WithHttpHealthCheck("/health");

builder.AddProject<Projects.Api>("api")
    .WithReference(partner);          // injects services__partner-api__https__0
```

Caveat: `WaitFor(externalService)` does not actually block startup in current Aspire — external services are observed but not gated on. Build resilience (Polly retries via `AddStandardResilienceHandler`) into the consumer for early-call failures.

## 5. Endpoints (network surface)

Every project / container resource has zero or more endpoints. Defaults:

- `AddProject<T>(...)` reads `Properties/launchSettings.json` and inherits the profile's HTTP/HTTPS bindings.
- `AddContainer(...)` exposes nothing by default.

Common operators:

| Operator | Effect |
|---|---|
| `.WithHttpEndpoint(port?, targetPort?, name?, isProxied?)` | Adds an HTTP endpoint. `targetPort` is the port inside the container/process; `port` is what the host binds. |
| `.WithHttpsEndpoint(...)` | Same but TLS. Required for gRPC over HTTP/2. |
| `.WithEndpoint(name, callback)` | Generic endpoint editor: change scheme, port, transport, etc. |
| `.WithEnvironment("PORT", endpointRef.Property(EndpointProperty.TargetPort))` | Inject the chosen port into the resource's environment. Common with `AddViteApp` / `AddNpmApp`. |
| `.WithExternalHttpEndpoints()` | Expose endpoints to external clients (e.g. browsers). |

Service discovery uses **endpoint names**, not ports. Multiple endpoints on the same resource appear as `services__<resource>__<endpoint-name>__0`. Default endpoint names are `http` and `https`; pick explicit names if a resource has more than one HTTP endpoint:

```csharp
var api = builder.AddProject<Projects.Api>("api")
    .WithHttpEndpoint(port: 5000, targetPort: 8080, name: "public")
    .WithHttpEndpoint(port: 5001, targetPort: 8081, name: "admin");
```

Consumer reads `https://api` (default) OR `https://_admin.api` (named-endpoint syntax).

## 6. Per-type recipes

### Web API

```csharp
var api = builder.AddProject<Projects.Contoso_Foo_Api>("api");
// auto-start, endpoints from launchSettings, AddServiceDefaults wires telemetry
```

If launchSettings has no HTTPS profile in CI, force one:

```csharp
var api = builder.AddProject<Projects.Contoso_Foo_Api>("api", launchProfileName: "https")
    .WithHttpsEndpoint();
```

### gRPC service

gRPC requires HTTP/2 over HTTPS (or h2c on plain HTTP). Aspire's HTTPS endpoint is HTTP/1.1+HTTP/2 capable on the same port via ALPN; bind explicitly:

```csharp
var grpc = builder.AddProject<Projects.Contoso_Foo_Grpc>("grpc")
    .WithHttpsEndpoint(port: 7100, targetPort: 8443, name: "https");

builder.AddProject<Projects.Contoso_Foo_Api>("api")
    .WithReference(grpc);     // services__grpc__https__0
```

Consumer (gRPC client):

```csharp
builder.Services.AddGrpcClient<MyService.MyServiceClient>(o =>
    o.Address = new Uri("https://grpc"));   // service discovery resolves
```

### Worker / hosted service

```csharp
var worker = builder.AddProject<Projects.Contoso_Foo_Worker>("worker")
    .WithReference(queue).WaitFor(queue);
```

If the worker exposes `/health` for liveness:

```csharp
.WithHttpEndpoint(targetPort: 8080, name: "health")
```

### CLI (one-shot)

```csharp
// Manual: dashboard "Start" button, or test code drives it.
var ingest = builder.AddProject<Projects.Contoso_Foo_Ingest>("ingest")
    .WithExplicitStart();

// Setup task: runs once before `api`, exits, never restarts.
var migrations = builder.AddProject<Projects.Contoso_Foo_Migrations>("migrations")
    .WithReference(db).WaitFor(db)
    .WithExplicitStart();

builder.AddProject<Projects.Contoso_Foo_Api>("api")
    .WithReference(db)
    .WaitForCompletion(migrations);
```

### Vite / Next / Node frontend

```csharp
var api = builder.AddProject<Projects.Contoso_Foo_Api>("api");

builder.AddViteApp("web", workingDirectory: "../../web", packageManager: "pnpm")
    .WithReference(api)
    .WithEnvironment("VITE_API_URL", api.GetEndpoint("http"))
    .WithHttpEndpoint(env: "PORT")
    .WithExternalHttpEndpoints();
```

### Container app

```csharp
var redis = builder.AddRedis("cache")
    .WithLifetime(ContainerLifetime.Persistent);

var partner = builder.AddContainer("partner", "wiremock/wiremock", "3.9.1")
    .WithBindMount("./stubs/partner", "/home/wiremock", isReadOnly: true)
    .WithHttpEndpoint(targetPort: 8080, name: "http");
```

### Executable resource (non-.NET binary)

```csharp
var nginx = builder.AddExecutable(
        "nginx",
        command: "/usr/sbin/nginx",
        workingDirectory: "../etc/nginx",
        args: "-g", "daemon off;");
```

`AddExecutable` is also the right pick when registering a CLI from outside the repo (no `.csproj`).

## 7. Cross-cutting operators

| Operator | When |
|---|---|
| `.WithEnvironment("KEY", "value")` | Plain env var. |
| `.WithEnvironment("KEY", endpointRef)` | Inject another resource's endpoint URL. |
| `.WithEnvironment("KEY", parameterRef)` | Inject a parameter. |
| `.WithArgs(args...)` | Append args to the executable command line. |
| `.WithBindMount(host, container, readOnly?)` | Mount a host path into a container. |
| `.WithDataVolume(name?)` | Create / reuse a named Docker volume for stateful containers. |
| `.WithHealthCheck("name")` | Custom health check (registered separately on `IServiceCollection`). |
| `.WithHttpHealthCheck(path, port?)` | HTTP probe at `path`, default success codes. |
| `.PublishAsConnectionString()` | At publish time, expose this resource only as a connection string (skip provisioning). |

## 8. Common pitfalls

- **`WaitFor` without a corresponding health check.** `WaitFor` evaluates `Healthy` state. If the dependency has no health check it never becomes healthy and `WaitFor` hangs. Add `.WithHttpHealthCheck("/health")` (HTTP services) or rely on the integration's built-in check (`AddPostgres`, `AddRedis`, etc. ship one).
- **`WithReference` without `WaitFor`.** The consumer starts before the dependency is ready. First requests fail. Add `WaitFor`, OR add resilience in the consumer (`AddStandardResilienceHandler`).
- **`RunAsEmulator()` after child resources.** The fluent type changes after `.AddDatabase("...")` / `.AddHub("...")` / etc. Call `RunAsEmulator()` before any child resource is appended.
- **Restart loop on a CLI.** Missing `WithExplicitStart()`. See § 3.
- **Service discovery name collision.** Two resources named `api` collide. Names must be unique within an AppHost.
- **gRPC over HTTP/1.1.** Default `WithHttpEndpoint` (no TLS) is HTTP/1.1 only. Use `WithHttpsEndpoint` for gRPC, or configure Kestrel for h2c manually.
- **`AddDockerfile` rebuilds on every run.** Use `WithBuildArg(...)` only when needed; cache layers carefully. For frequently-iterated services prefer `AddProject` (faster .NET incremental builds).
